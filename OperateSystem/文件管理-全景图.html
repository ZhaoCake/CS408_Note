五个模块 （对应考纲三块：文件 / 目录 / 文件系统）

A 文件的身份与操作 文件的基本概念 / 元数据 / 操作 / 保护

  • 数据项（最低级）→ 记录 → 文件；无结构文件（流式，按字节）／有结构文件（记录式；目录也是特殊的有结构文件）
  • FCB：存放控制文件所需信息，实现 按名存取；FCB 的有序集合 = 文件目录，一个 FCB = 一个目录项；FCB 必须连续存放
  • inode：把文件名与描述信息分开，描述信息单独成索引结点；分磁盘索引结点 / 内存索引结点（多记“是否被修改、几个进程在用”）
  • 六种操作：create、write、read、重定位（只设位置不读写）、delete、截断（属性不变、长度归零）
  • 打开：FCB 副本进 系统打开文件表（全系统仅一张，含打开计数器）→ 返回 fd；此后内核只能靠 fd 访问，不能再靠文件名
  • read / write 参数：文件描述符 + 缓冲区首址 + 传输字节数（不需要文件名和路径）；open 参数：路径 + 文件名 + 操作类型
  • 进程打开文件表：每进程一张，存指向系统表的指针 + 文件指针（本进程独有）
  • 保护：口令（存 FCB/inode）／加密／访问控制 ACL（粒度小、灵活性高）；Linux 九位 = 3 组 ×（读, 写, 执行）；用户 n 类、权限 m 种 → 至少 n×m 位

B 逻辑结构 文件的逻辑结构

  • 无结构文件：以字节为单位，没有结构只能穷举搜索；适合源程序、目标代码
  • 顺序文件：串结构（按存入时间，与关键字无关）／顺序结构（按关键字）；定长记录可随机存取 Aᵢ = i×L，可变长记录不能随机存取；批量读写的效率是所有逻辑文件中最高的
  • 索引文件：每条记录一个索引项；记录可离散存放，索引表必须连续存放；索引表本身是定长顺序文件 → 可随机访问；用于实时性要求高的场合
  • 索引顺序文件：一组记录对应一个索引项，组间有序、组内无序；N 条记录分成 √N 组 → 约 √N 次查找
  • 散列 / 直接文件：键值经散列函数直接决定物理地址；存取快，但会冲突
  • 逻辑记录是对文件进行存取的基本单位

C 物理结构 本章核心 · 最爱考

① 连续分配

物理块号 = 起始块号 + 逻辑块号；支持顺序 + 随机访问，顺序读写最快、寻道最少；不利于拓展（末尾块可能已分配、要大量移动盘块）、有难以利用的外部碎片、只适用于长度固定的文件

② 链接分配 · 隐式链接

FCB 记起始 + 结束块号（及长度），块内放指向下一块的指针（对用户透明）；读第 i 号逻辑块需 i+1 次磁盘 I/O；不支持随机访问、中间损坏则后面全丢；簇：几个盘块组成簇按簇分配 → 成倍减少查找时间，代价是增加内部碎片

③ 链接分配 · 显式链接 FAT

指针集中存进内存的文件分配表 FAT，FCB 只记起始块号；一个磁盘仅一张 FAT，开机读入并常驻内存 → 地址转换不需要读磁盘；表项物理连续、等长 → “物理块号”字段可隐含；表项位数决定总块数（16 bit → 2¹⁶ 块），FAT 总大小 = 表项数 × 表项大小

④ 索引分配（※※※）

每个文件一张索引表（逻辑块号隐含 + 物理块号），功能类似页表；支持随机访问、无碎片、方便拓展；单个文件长度与索引结点个数无关；链接方案查找效率低；K 层索引且顶层未调入内存 → 访问一个数据块需 K+1 次读盘，小文件也不例外；混合索引让“小文件用较少读盘次数”就能命中

容量计算（混合索引）

每索引块可放 盘块大小 ÷ 索引项大小 个索引项；典型（盘块 4 KB、索引项 4 B）→ 1 K = 2¹⁰ 项：
10 个直接项 = 40 KB；一级间接 4 MB；二级间接 4 GB；三级间接 4 TB

D 目录与共享 目录 / 硬链接与软链接

  • 演进主线：单级（全系统一张表，不许重名、查找慢）→ 两级（MFD 主文件目录 + UFD 用户文件目录，允许重名、不能分类）→ 树形（不同目录可重名、检索快，但不便于共享、逐级访问磁盘次数多）→ 无环图（增加指向同一结点的边，方便共享）
  • 共享计数器：删除请求只删该用户的 FCB 并计数 −1，当且仅当计数为 0 才真正删除结点
  • 绝对路径（从根出发）／相对路径（从当前目录出发，更常用）；多级目录中从根到任一文件有且只有一条路径
  • 硬链接（基于索引结点）：与被链接文件指向同一索引结点，引用计数 +1；count = 0 才真删；查找比软链接快；一般不能跨文件系统
  • 软链接（基于符号链）：独立的 Link 类型文件（快捷方式），指向不同索引结点；可跨文件系统、可指向目录；创建/删除软链接、删除被链接文件，count 都不变
  • 共享 ≠ 复制：系统中只有一份数据，一人修改所有人可见；硬/软链接都多出一个文件名 → 全目录转储到顺序载体时会产生多份副本

E 文件系统全局 布局 / 空闲空间 / VFS / 挂载

  • 五层结构：应用程序 → 逻辑文件系统（目录与元数据、打开文件表）→ 文件组织模块（记录号 → 逻辑地址）→ 基本文件系统（逻辑地址 → 物理地址）→ I/O 控制（驱动 + 中断）→ 设备
  • 格式化：物理格式化（低级：划分扇区、检测坏扇区并用备用扇区替换）→ 逻辑格式化（划分分区/分卷、完成文件系统初始化、建立根目录）
  • 磁盘布局：MBR（0 号扇区 + 分区表，确定活动分区）→ 引导块（自带格式，因引导时还不能解释文件系统格式）→ 超级块（块数量/大小、空闲块数量与指针、空闲 FCB…，启动或首次使用时载入内存）→ inode 区 → 文件数据块
  • 内存结构：超级块副本、挂载表、目录项高速缓存、系统/进程打开文件表
  • 空闲空间四法：空闲表法（连续分配，首次/最佳/最坏适应；回收：两侧都空闲表项 −1、一侧空闲不变、都不空闲 +1）／空闲链表法（空闲盘块链适用离散、空闲盘区链分配多块效率更高）／位示图法／成组链接法（UNIX：最后一个空闲盘块作“成组链块”存下一组，系统只存指向第一个成组链块的指针）
  • VFS：为用户提供统一接口、屏蔽底层差异；面向对象思想定义通用模型；严格来说不是实际的文件系统，只存在于内存中；四对象 = 超级块对象 / 索引结点对象 / 目录项对象 / 文件对象
  • 挂载 mounting：使用前必须挂载；在 VFS 中注册，内存挂载表记录类型、容量；新文件系统提供函数地址列表；挂载点 = 某个父目录

选择题判据轴：四问 + 三补

① 支持随机访问？ 连续 ✓｜隐式链接 ✗｜FAT ✓｜索引 ✓
② 有外部碎片？ 只有连续分配有
③ 方便文件拓展？ 只有连续分配不方便
④ 要读几次盘？ 隐式链接 i+1 次｜K 层索引 K+1 次｜FAT 转换 0 次
补 1 占额外空间？ FAT / 索引表 / 指针都要
补 2 要先知道大小？ 连续分配必须先确定；链接、索引不用
补 3 中间损坏？ 隐式链接会丢掉后面全部数据
再补 空闲管理归属：连续 ↔ 空闲表；离散 ↔ 空闲盘块链；两者皆可 ↔ 位示图、成组链接

必会公式与易错

  • 每索引块项数 = 盘块大小 ÷ 索引项大小
  • 混合索引：40 KB / 4 MB / 4 GB / 4 TB
  • 位示图（0 开始）：b = n×i + j，i = b÷n，j = b mod n
  • 索引顺序文件：N 条记录 ≈ √N 次查找
  • 顺序文件定长记录：Aᵢ = i×L
易错：open 后只能用 fd；FCB 必须连续存放；索引文件的记录可离散、索引表必须连续；位示图按 0 开始算；成组链接中“指向下一组的空闲盘块不参与分配”；VFS 只在内存；多层索引下小文件也要 K+1 次读盘；软链接不影响 count；提前读只对顺序访问有效。
