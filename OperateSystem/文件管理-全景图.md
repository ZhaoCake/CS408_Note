# 第四章 文件管理 — 全景图

> 用途：把"杂"变成"有主线的树"。先看主线，再看四个模块，最后查判据轴与公式表。
> 素材来源：`EX-选择题考点总结/EX-第四章考点总结.md`（考纲+考点）、`课程笔记/3-file-management.md`（知识导图骨架）、`markji/操作系统/第4章-文件管理/`（22 张卡片）、`EX-OS相关总结.md` 第四章。

## 一、一句话主线

**文件管理 = 把"用户眼里的字节流/记录流"，映射成"磁盘上的物理块"，并负责找到它、共享它、复用那些空闲块。**

这条主线只有三个动词，全章都在重复它们：

1. **描述**：这东西是什么？（文件、元数据、FCB、inode、目录）
2. **映射**：用户在逻辑上看到什么 → 磁盘上实际放在哪？（逻辑结构、物理结构）
3. **支撑**：系统怎么把这些事高效管起来？（层次结构、磁盘/内存布局、空闲空间管理、VFS、挂载）

## 二、数据流动的完整路径（背这一条就不迷路）

```
用户程序
  │  ① 给出「路径 + 文件名」
  ▼
逻辑文件系统 ──► 逐级检索目录（只比文件名）──► 找到目录项目录项 FCB / inode
  │  ② open 成功：FCB 副本进入【系统打开文件表】，进程打开文件表加一条指向它的指针
  │      返回 fd（文件描述符）──► 之后内核只能靠 fd 访问，不能再靠文件名
  ▼
文件组织模块 ──► 记录号 → 逻辑块号
  ▼
基本文件系统 ──► 逻辑块号 → 物理块号（★ 连续/链接/索引 三种物理结构，唯一区别就在这一步）
  ▼
I/O 控制（设备驱动程序 + 中断处理程序）──► 磁盘
  │  ③ 空闲块从哪来？──► 空闲表/空闲链/位示图/成组链接
  ▼
磁盘布局：MBR → 引导块 → 超级块 → inode 区 → 数据块
```

> 记住两个"分水岭"：
> - **inode 把「文件名」和「描述信息」拆开** → 目录检索只比文件名，检索变快。
> - **物理结构三兄弟的差别，只在"逻辑块号 → 物理块号"这一步怎么算**。

## 三、模块 A：文件的"身份"与操作（考纲 1 前半 + 文件操作 + 保护）

### A1 基本概念
- 文件：以硬盘为载体、存储在计算机上的信息集合；**用户 I/O 的基本单位**。
- 组织形式：无结构文件（流式，二进制/字符流）／有结构文件（记录式，一组相似记录组成）。**目录也是一种特殊的有结构文件**；UNIX 中所有设备都是特殊文件。
- 层次：**数据项（最低级，基本数据项是最小逻辑单位）→ 记录（相关数据项的集合）→ 文件**。
- 逻辑记录是**对文件进行存取的基本单位**。

### A2 元数据：FCB 与 inode（全章的地基）
| | FCB（文件控制块） | 索引结点 inode |
|---|---|---|
| 是什么 | 存放控制文件所需信息的数据结构，实现**按名存取** | 把文件的描述信息单独抽出形成的数据结构 |
| 关系 | **FCB 的有序集合 = 文件目录，一个 FCB = 一个目录项**；FCB 必须**连续存放** | 引入后目录项只需存「文件名 + inode 号」 |
| 类型 | — | **磁盘索引结点**（在外存）／**内存索引结点**（额外记录：文件是否被修改、几个进程正在访问等） |
| 解决的问题 | 按名存取、同目录不允许重名 | 极大提升检索速度、节省系统开销 |

- 文件属性：文件名、标识符、类型、位置、大小、创建/修改时间、创建者、所有者、保护信息等。
- **文件索引结点维护的是文件的物理结构**（不是逻辑结构）。

### A3 文件操作
- 六种：创建 create、写 write、读 read、**重定位（寻址，只设位置不读写）**、删除 delete、**截断（属性不变，长度归零并释放空间）**。
- read/write 共用**同一指针**（当前文件位置指针）；参数 = **文件描述符、缓冲区首址、传输字节数**（**不需要文件名和路径**）。
- `open` 参数 = **文件存放路径、文件名、操作类型**（r / rw…）。
- **打开 = 把 FCB 从外存复制到内存的系统打开文件表，并返回表目编号（fd）**。
- 打开后 → 只能靠 **fd / 文件句柄**访问；再次操作时靠索引查表，省掉重新检索目录的开销。

### A4 两张打开文件表（高频对比）
| | 系统打开文件表 | 进程打开文件表 |
|---|---|---|
| 数量 | 系统仅**一张** | 每进程一张 |
| 内容 | 打开的 **FCB 副本** + **打开计数器 Open Count** | 指向系统表条目的**指针** + 上次读写位置的**文件指针** |
| 关闭 | `close` 使计数递减，**Open Count = 0** 才可删除条目 | 文件指针对该进程唯一，必须与磁盘文件属性分开存放 |

- **文件名不必是打开文件表的一部分**；**多个进程共享同一文件时，系统打开文件表只有一个对应表项**；进程不保证互斥。

### A5 文件保护
- **口令保护**（口令存在 FCB 或 inode 中）、**加密保护**（系统存的是加密后的数据）、**访问控制**（FCB/inode 中加 **ACL**，粒度小但灵活性高）。
- Linux 九位权限：所有者／同组用户／其他用户，每组依次 可读、可写、可执行。
- 通用公式：用户类别 n 种、访问权限 m 种 → **至少 n×m 位**。

## 四、模块 B：文件"内部长什么样" —— 逻辑结构（考纲 1 后半）

| 逻辑结构 | 关键点 | 检索特点 |
|---|---|---|
| 无结构/流式 | 以字节为单位、只能穷举搜索 | 管理简单，适合源程序、目标代码 |
| 顺序文件 | 记录顺序排列；**串结构**（按存入时间，与关键字无关）／**顺序结构**（按关键字） | 定长记录可随机存取 **Aᵢ = i×L**；可变长记录**不能**随机存取；**批量读写效率是所有逻辑文件中最高的** |
| 索引文件 | 每条记录一个索引项；**记录可离散存放，索引表必须连续存放** | 索引表本身是定长顺序文件 → 可随机访问；用于实时性要求高的场合 |
| 索引顺序文件 | **一组记录对应一个索引项**；组间有序、**组内无序** | N 个记录分 **√N 组** → 约 **√N 次**查找；省索引空间、比顺序找得快 |
| 散列/直接文件 | 键值经散列函数直接决定物理地址 | 存取快，但会冲突 |

## 五、模块 C：文件"落在磁盘哪里" —— 物理结构（本章最核心、最爱考）

### C1 三种分配方式对比（背这张表就够答选择题）
| 判据 | 连续分配 | 链接分配-隐式 | 链接分配-显式(FAT) | 索引分配 |
|---|---|---|---|---|
| 块映射 | 物理块号 = **起始块号 + 逻辑块号** | FCB 记起始/结束块号，块内放下一块指针（对用户透明） | FCB 只记**起始块号**，指针集中放进 **FAT** | 每个文件一张**索引表**（逻辑块号隐含 + 物理块号） |
| 随机访问 | ✅ | ❌ | ✅ | ✅ |
| 外部碎片 | 有（难利用） | 无 | 无 | 无 |
| 方便拓展 | ❌（末尾块可能已分配，需大量移动盘块） | ✅ | ✅ | ✅ |
| 额外开销 | 空间利用率低 | 指针开销、中间损坏则后面全丢 | FAT 占存储空间 | 索引表本身要读盘 |
| 读盘次数 | 最少（寻道/寻道时间最小） | 读第 i 号逻辑块需 **i+1 次** I/O | 地址转换**不需要读磁盘**（FAT 常驻内存） | K 层索引且顶层未调入内存 → **K+1 次**读盘 |

### C2 细节补刀
- **簇（cluster）**：几个盘块组成簇按簇分配 → 成倍减少查找时间、指针占比小，代价是**增加内部碎片**；**文件占用空间一定是簇大小的整数倍**。
- **FAT**：各表项物理上连续、长度相同 → "物理块号"字段可隐含；**一个磁盘仅一张 FAT**，开机读入并**常驻内存**；**表项位数决定总块数**（16 bit → 最多 2¹⁶ 块），**FAT 总大小 = 表项数 × 表项大小**。
- **多层索引**：各层索引表大小不得超过一个磁盘块（同多级页表）；缺点是**小文件也要 K+1 次读盘**。
- **混合索引**：直接地址项 → 一级间接 → 二级 → 三级，让**小文件用较少读盘次数**即可命中。
- 链接方案：多个索引块串起来，FCB 只记第一个索引块号，**查找效率低**。
- **单个文件长度与索引结点个数无关**。

### C3 必会计算
- 每索引块可放索引项数 = **盘块大小 ÷ 索引项大小**。
- 典型数据（盘块 4 KB、索引项 4 B）：每索引块 1 K = 2¹⁰ 项；**10 个直接项 → 40 KB；一级间接 → 4 MB；二级 → 4 GB；三级 → 4 TB**。
- 混合索引定位逻辑页 n：A 个直接项、每块 k 个地址项时
  - n < A：直接项；
  - A ≤ n < A+k：一次间址第 n−A 项；
  - A+k ≤ n < A+k+k²：二次间址，一级索引 ⌊(n−A−k)/k⌋，块内第 (n−A−k) mod k 项；
  - 三次间址同理逐层取模/整除。
- 最大文件长度（地址位数 m、块大小 N 字节）：链接分配 ≈ **2ᵐ·(N − m/8)**（别忘减指针开销）；索引分配 = **Σₖ (N·8/m)ᵏ · N**（k 为间接次数）。
- FCB 需额外字段：链接分配【文件首地址 + 最后一块块号】；连续分配【文件首地址 + 文件大小】。

## 六、模块 D：目录与共享（考纲 2）

### D1 目录结构演进（一条线：解决重名 → 解决分类 → 解决共享）
```
单级目录（全系统一张表：不许重名、查找慢、不便共享）
  → 两级目录（MFD 主文件目录 + UFD 用户文件目录：允许重名，但不能分类）
    → 多级/树形（不同目录可重名、检索快；但不便于共享、逐级访问磁盘次数多）
      → 无环图目录（加一条指向同一结点的边，方便共享）
```
- 绝对路径（从根出发）／相对路径（从当前目录出发，更常用）；**多级目录中从根到任一文件有且只有一条路径**。
- **共享计数器**：删除请求只删该用户的 FCB 并计数 −1，**当且仅当计数为 0 才真正删结点**。
- 目录管理四要求：按名存取、提高检索速度、提供访问控制信息、允许不同用户对不同文件用相同名字。

### D2 硬链接 vs 软链接
| | 硬链接（基于索引结点） | 软链接（基于符号链） |
|---|---|---|
| 本质 | 与被链接文件**指向同一索引结点**，count +1 | 独立文件实体（Link 类型，相当于快捷方式），指向**不同**索引结点 |
| 引用计数 | 新建文件默认 1；创建 +1、删除 −1；**count = 0 才真删** | 创建/删除软链接、删除被链接文件，**count 都不变** |
| 跨文件系统 | 一般不能 | **可以** |
| 指向目录 | 一般只用于文件 | **可以指向文件或目录** |
| 速度 | **比软链接快** | 较慢 |
- 共享 ≠ 复制：共享时系统只有一份数据，一人修改所有人可见。
- 读写指针：源文件和硬链接各自维护 fd，读写指针位置不一定相同。
- 无论硬/软链接都会多出一个文件名 → **全目录转储到磁带等顺序载体时会产生多份文件副本**。

## 七、模块 E：文件系统全局（考纲 3）

### E1 层次结构（自顶向下，五层）
```
应用程序
  → 逻辑文件系统/文件目录系统：管目录与元数据，找 FCB/inode，管打开文件表、活跃文件目录表
    → 文件组织模块：记录号 → 逻辑地址
      → 基本文件系统/物理文件系统：逻辑地址 → 物理地址，向驱动发通用命令
        → I/O 控制：设备驱动程序 + 中断处理程序
          → 设备（最底层）
```

### E2 磁盘布局（外存结构）
```
MBR（0 号扇区 + 分区表，确定活动分区）
  → 引导块（启动该分区的操作系统；自带格式，因为此时还不能解释文件系统格式）
    → 超级块（文件系统的所有关键信息：块数量/块大小/空闲块数量与指针/空闲 FCB 数量与指针…，启动或首次使用时载入内存，需与磁盘副本一致）
      → inode 区（所有 inode 有共同起始地址，大小固定；按编号可迅速定位）
        → 文件数据块
```
- 磁盘初始化两步：**物理格式化（低级格式化：划分扇区、检测并替换坏扇区）** → **逻辑格式化（划分分区/分卷，完成各分区文件系统初始化、建立根目录、初始化空闲块管理数据结构）**。
- 引导扇区在**安装操作系统时**写入，由操作系统决定。

### E3 内存结构
- 超级块副本、**挂载表 mount table**、目录项高速缓存、系统打开文件表、进程打开文件表、位示图/FAT 之类的常驻结构。

### E4 外存空闲空间管理（必考，四种）
| 方法 | 组织 | 适用 | 关键点 |
|---|---|---|---|
| 空闲表法 | 每个空闲区一个表项 | 连续分配 | 分配用首次/最佳/最坏适应；回收表项数：前后都空闲 **−1**，一侧空闲 **不变**，都不空闲 **+1** |
| 空闲链表法 | 空闲盘块链 | 离散分配 | 申请 K 块从链首依次摘下，回收挂链尾 |
| 空闲链表法 | 空闲盘区链 | 离散+连续 | **分配多个盘块效率更高、链更短**；回收时相邻则合并 |
| 位示图法 | 一个二进制位 = 一个盘块 | 都适用 | 从 0 编号：**b = n×i + j**，i = b÷n，j = b mod n（n 为字长，i 字号/行，j 位号/列）；从 1 编号则先减 1 再算 |
| 成组链接法（UNIX） | 一组空闲盘块号存在一个盘块中，其**最后一个空闲盘块作为成组链块**存下一组 | 大型文件系统 | 系统只存**指向第一个成组链块的指针**；分配时指针下移一格，遇到成组链块要**先把该块读入内存再指向新链块第一条记录**；回收时指针上移一格记入，**满 n 个**就把当前 n 个块号写入新回收的盘块（它成为新的成组链块） |

> 成组链接的坑：**当前组中"指向下一组"的那个空闲盘块不参与分配**。

### E5 VFS 与挂载
- **VFS**：为用户提供**统一接口**、屏蔽底层差异；采用**面向对象**思想定义通用模型；**严格来说它不是实际的文件系统，只存在于内存中、不存在于任何外存空间**；系统启动时建立、关闭时消亡；能提高性能。
- **VFS 四对象**：超级块对象（已挂载的特定文件系统）、索引结点对象（一个特定文件）、目录项对象（一个特定目录项）、文件对象（与进程相关的已打开文件）。
- 性能来源：最近最常使用的**目录项对象放进目录项高速缓存**，加速"路径名 → inode"的转换。
- **挂载 mounting**：每个分区可建独立文件系统，使用前必须挂载；在 VFS 中注册，内存挂载表记录文件系统类型、容量等；新文件系统要向 VFS 提供**一个函数地址列表**；挂载点 = 某个父目录。
- UNIX 用系统根文件系统（内核在引导阶段直接安装），其他文件系统由初始化脚本或用户安装。

## 八、选择题判据轴（四个字：碎、随、扩、盘）

看到物理结构/空闲管理题，按这四轴逐个排除：
1. **随机访问支持吗？** 连续 ✅ / 隐式链接 ❌ / 显式链接 ✅ / 索引 ✅
2. **有外部碎片吗？** 连续有；链接与索引无
3. **方便拓展吗？** 连续不方便；其余方便
4. **要读几次盘？** 隐式 i+1 次；多层索引 K+1 次；FAT 转换 0 次

再补三轴：**占用额外空间吗**（FAT/索引表/指针）、**与文件大小有关吗**（连续分配要先知道大小；链接/索引不用）、**中间损坏会怎样**（隐式链接后续全丢）。

## 九、易错清单（来自本人笔记与卡片解析）

- `open` 后内核**不能**再用文件名访问文件，只能用 fd/句柄。
- **文件名不必是打开文件表的一部分**；read/write **不需要文件名和路径**。
- FCB **必须连续存放**；同一目录下**不允许重名**。
- 索引文件的**记录可离散，索引表必须连续**。
- 顺序文件"批量读写效率最高"，但**串结构/可变长记录无法随机存取**。
- **引入索引节点前**目录项存 FCB；**引入后**只存文件名 + 索引节点编号。
- 位示图公式按 **0 开始**（408 多按 0 开始出算）。
- 成组链接"指向下一组的空闲盘块不参与分配"。
- VFS **只在内存**；inode 区在磁盘。
- 多层索引下**小文件也要 K+1 次读盘**。
- 硬链接 count = 0 才真删；软链接**不影响 count**。
- 提高文件访问速度五招：提前读（**仅对顺序访问有效**）、延迟写（页缓冲区队列属共享资源）、分配连续簇、磁盘高速缓存、内存映射文件。
- 逻辑地址 vs 物理地址：所有**指针指向的是逻辑地址**，存页/段基址的寄存器存物理地址。
