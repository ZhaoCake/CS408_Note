# 408 制卡规范（方法论 + 格式标准）

> 配套文档：`markji/墨墨记忆卡制卡指南.md`（Markji 官方语法速查）。
> 本文件规定**从课程笔记提取考点的思路**和**卡片的标准格式**。制卡前必须同时通读两份文档。

---

## 一、素材与覆盖策略

### 1.1 双源交叉覆盖

| 来源 | 作用 | 优先级 |
|---|---|---|
| `EX-考点总结/`（各章） | 制卡骨架。逐条扫描，每条编号必须"出卡或记跳过理由" | ★★★ 主源 |
| `课程笔记/*.md` | 补充源。提取 `==高亮==`、`**注意**`（含橙色注意块）、加粗结论句、表格条目 | ★★ 补漏 |
| 课程笔记中的表格 | 对比类考点集中地，每张表至少评估一次是否出对比卡 | ★★ 补漏 |
| 长推演例题、图片导图、复习提示 | **不出卡**，最多抽取其中可直接背诵的结论 | ✕ |

### 1.2 逐章制卡流程（每章一个批次）

1. 通读该章 EX 考点总结，按编号列出**考点清单**（一行一考点，标注来源与 ※ 级别）
2. 通读该章课程笔记，补充清单中遗漏的高亮/注意/表格考点
3. 逐条映射为卡片：一考点 → 一卡（多面考点拆成多卡）
4. 无法成卡的条目在清单中标注跳过理由（如"依赖图示""纯叙述"）
5. 按本规范的命名规则写入对应章节目录，并更新 `markji/制卡进度.md`

### 1.3 覆盖率要求

- EX 总结中带 `※` 的条目、加粗结论句：**100% 成卡或记录跳过理由**
- 普通条目：能独立背诵的都成卡；上下文依赖过强的可合并为一张卡
- 课程笔记高亮/注意句：与 EX 重复的不重复出卡，笔记独有的补卡

## 二、卡片基本结构：填空 + 解析（核心约定）

**所有卡片一律采用"正面填空句 + 解析"结构**，不做纯问答/简答卡：

```text
[P#H1#类型]
正面：包含该考点的陈述句，只对重点内容挖空。
---
解析：该知识点的完整说明，作为背诵材料。
```

### 2.1 正面（填空句）规则

- 用**陈述句**呈现知识点的核心结论，对重点处挖空 `[F#n#]`；挖空后正面仍必须是**自足可读**的完整句子，不依赖解析就能理解在问什么
- 每卡挖空 **1~4 处**；超过 4 个重点的知识点拆成多卡
- 关联的成组内容（如同类的多个数、对比两端）用连续编号或同编号分组

### 2.2 重点判断标准（挖什么、不挖什么）

挖空对象是**"答题时的得分点"**，即这句话里最可能记错、记漏、考场上需要主动回忆的成分：

| 必挖 | 例子 |
|---|---|
| 数值与单位 | 覆盖直径约 `10m`、`1 Baud = log2M bit/s` |
| 专有名词/协议/算法/设备名 | 令牌环、介质访问子层、集线器、ARP |
| 层归属/类别归属 | 对应 OSI 下三层、属于网络层协议 |
| 方向性/关系性结论 | 协议"水平"、服务"垂直"、点到点 vs 端到端 |
| 正误关键词 | "最基本功能是数据通信"、"仅有面向连接"、"不保证有序" |
| 公式的组成项 | 发送时延=数据长度/信道带宽 |
| 分类标准与阶段名 | RFC 三阶段、电路交换三阶段 |

**不挖**：背景引入语、比喻和举例的通用描述、修饰性定语、正面其他句已出现过的信息、解析中才出现的补充细节。

### 2.3 解析（`---` 之后）规则

- 给出该知识点的**完整说明**：完整定义、全部要点、补充细节，是"背下来"的材料，不是正面句子的简单重复
- 解析内合理使用强调语法（见第三节），把记忆锚点标出来
- 易错/易混点用红字点破；全卡唯一的必背结论用黄底（放在正面或解析中均可，一卡 ≤1 处）

## 三、强调语法使用规范（颜色 / 加粗 / 底色）

约定如下（颜色均为 6 位小写十六进制）：

| 语法 | 用途 | 频率约定 |
|---|---|---|
| `[T#B#...]` 加粗 | 关键词、判定词 | 每卡 1~3 处 |
| `[T#!e53935#...]` 红字 | 错误说法、否定词（"并非/不能/≠"）、易混点 | 仅易错/对比类内容，每卡 ≤2 处 |
| `[T#!!fff59d#...]` 黄底 | 一张卡唯一的必背核心结论 | 每卡 ≤1 处 |
| `[T#!1e88e5#...]` 蓝字 | 补充备注、口诀（可选） | 可选 |

**克制原则**：强调是手段不是装饰——任何一处强调都必须服务于"这块我会不会记错/记漏"；无信息量的整句标红、大面积铺底色一律禁止。

## 四、卡片类型与模板

考点先判断形态，再套用对应类型标签与模板。所有模板共用"填空 + 解析"结构。

| 类型代码 | 考点形态 | 典型例子 |
|---|---|---|
| `概念` | 名词定义、"XX 是什么" | PCB 是进程存在的唯一标志 |
| `判据` | 结论性判据、"什么决定什么" | 存储字长决定 MDR 位数 |
| `对比` | 易混淆的成对/成组对象 | TCP vs UDP 边界处理 |
| `数字` | 端口、字段长度、窗口范围 | DNS 端口 53 |
| `公式` | 性能/时间/复杂度公式 | 平均访存时间公式 |
| `流程` | 算法步骤、协议过程 | 三次握手、中断处理流程 |
| `易错` | "需要注意"、反例、正误对 | PPP 信息段是 0~1500 而非 46~1500 |
| `场景` | "什么情况下选什么" | n 大且关键字可分解 → 基数排序 |

### 模板 1：概念/数字卡

```text
[P#H1#概念]
计算机网络的三大主要功能是数据通信、[F#1#资源共享]及[F#2#分布式处理]，其中最基本的功能是[F#3#数据通信]。
---
解析：数据通信是实现其他功能的基础。其余功能还有信息综合处理、提高可靠性、负载均衡。
```

### 模板 2：对比卡（易混淆概念）

```text
[P#H1#对比]
协议是[F#1#水平]方向的，控制对等实体间的通信；服务是[F#2#垂直]方向的，由下层通过[F#3#层间接口]向上层提供。
---
解析：上层只能通过相邻层间的接口使用下一层的服务，不能调用其他层的服务；下层服务的实现细节对上层透明。
两台主机通信时，对等层在逻辑上有一条直接信道，表现为不经过下层就把信息传送到对方。
```

### 模板 3：公式卡

```text
[P#H1#公式]
发送时延 = [F#1#数据长度 ÷ 信道带宽]；传播时延 = [F#2#信道长度 ÷ 电磁波传播速率]。
---
解析：总时延 = 发送时延 + 传播时延 + 排队时延 + 处理时延；做题时排队时延和处理时延一般可忽略不计（除非题目另有说明）。
复杂公式用独立公式块：
[E##时延带宽积=传播时延×带宽]
```

### 模板 4：流程卡

```text
[P#H1#流程]
电路交换的三个阶段：① [F#1#建立连接]（电路建立）；② 通信；③ [F#2#释放连接]（拆除电路）。
---
解析：电路交换链路支持多路复用。步骤超过 5 步时拆成"整流程卡 + 单步细节卡"。
```

### 模板 5：易错卡

```text
[P#H1#易错]
高速链路提高的仅是[F#1#数据发送速率]，而非比特在链路上的[F#2#传播速率]。
---
解析：提高发送速率只是为了减少发送时延。
[T#!e53935#传播时延只取决于信道长度和电磁波传播速率，与带宽无关。]
```

## 五、文件命名与存放

- 路径：`markji/<课程>/<第N章-章节名>/<NN>-<考点短名>.txt`
- `NN` 为章内两位序号（01、02…），按考点在 EX 总结中出现的顺序编
- 考点短名：3~8 字中文，见名知义；禁止空格和正反斜杠

示例：

```text
markji/计算机网络/第3章-数据链路层/01-码元定义.txt
```

## 六、质量红线（出卡前自查）

1. **填空+解析结构**：一律不做简答/问答卡；正面是挖空陈述句，解析在 `---` 后
2. **正面自足**：挖空后正面仍是完整可读的句子，不看解析也知道在考什么
3. **重点判断**：只挖"得分点"（数值/名词/归属/方向/正误关键词/公式组成），背景与修饰不挖；每卡 ≤4 空
4. **原子性**：一卡一考点；长枚举拆卡，不整段塞入
5. **数字完整**：所有数值、单位、范围必须精确照录笔记，不得凭记忆改写
6. **解析是背诵材料**：给出完整说明，而不是正面句子的重复；易错点用红字、必背结论用黄底
7. **图片依赖内容不出卡**；确有价值的只抽文字结论
8. **语法自查**：按《墨墨记忆卡制卡指南》第七节 12 项清单过一遍（含挖空编号为正整数、中括号转义）
9. **来源可溯**：每章批次结束后更新 `00-制卡清单.md`（考点 → 卡片文件名 / 跳过理由），供抽查

## 七、覆盖率审计（自动校验）

每章（或每批次）完成后运行 `scripts/coverage_audit.py` 自动审计，四通道：

| 通道 | 作用 | 主要产出 |
|---|---|---|
| ① 正向覆盖 | EX 考点条目 → 卡片 | 未覆盖/跨章条目清单（驱动补卡） |
| ② 笔记补漏 | 笔记高亮/加粗/注意/表格 → 卡片 | 疑似漏卡（需人工甄别） |
| ③ 反向溯源 | 卡片挖空词 → 笔记 | 无依据卡片清单 |
| ④ 词频盲区 | 笔记高频词 → 卡片 | 盲区探测 |

审计产出：`markji/覆盖率报告/`（README 汇总 + 每章报告）。**要求**：
- EX 考点条目"完全覆盖"比例作为硬指标，批次提交前跑一次
- 未覆盖/跨章条目必须逐条人工甄别：真漏卡 → 补卡并更新清单；例题/比喻/跨章 → 在章清单记录理由
- 反向溯源报出的"无依据挖空词"需人工确认（区分词形差异误报与真实无依据）

依赖：`pip install jieba`。审计结果不影响卡片内容，只驱动补卡与记录。

## 八、预估规模与推进方式

- 以 EX 总结密度估计：全仓库约 **600~900 张**（DS 约 180、CO 约 220、OS 约 200、CN 约 200，实际以逐章扫描为准）
- 推进方式：按"章"为批次（每次一章），出卡 + 更新清单与进度 → 用户抽查 → 提交
- 顺序：计算机网络 → 操作系统 → 计算机组成原理 → 数据结构
